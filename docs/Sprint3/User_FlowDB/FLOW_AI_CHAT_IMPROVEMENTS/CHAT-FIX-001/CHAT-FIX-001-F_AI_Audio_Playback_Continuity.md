# [Fix] CHAT-FIX-001-F AI 음성 재생 연속성

## User Story

사용자는 AI Chat에서 AI가 말할 때 단어 일부가 빠지거나 문장이 점프되는 느낌 없이 자연스럽게 이어지는 음성을 들어야 한다.

---

## 완료 기준(AC)

- [ ] AI 응답 음성이 중간에 단어가 빠진 것처럼 잘려 들리지 않는다.
- [ ] 짧은 AI 응답과 긴 AI 응답 모두 시작, 중간, 말끝이 자연스럽게 재생된다.
- [ ] AI 음성이 실제로 끝나기 전에는 마이크 버튼이 다시 활성화되지 않는다.
- [ ] AI 음성이 끝난 뒤에는 output level과 마이크 버튼 상태가 정상으로 돌아온다.
- [ ] 재생 안정성을 확인할 수 있도록 audio 수신, 재생 시작, 재생 종료 경계를 로그로 확인할 수 있다.
- [ ] 수정 후에도 마이크 버튼 비활성화, final 자막 표시, 사용량 기록 흐름은 기존처럼 동작한다.

## 문제 가설

현재 증상은 AI 음성이 단순히 버벅이는 수준이 아니라, 단어 일부가 빠져 문맥 이해가 어려워지는 형태다. 이 경우 UI 애니메이션보다 로컬 오디오 스트리밍 처리 쪽을 먼저 의심해야 한다.

- OpenAI Realtime은 AI 음성을 하나의 파일이 아니라 여러 PCM audio chunk로 내려준다.
- 앱은 이 chunk들을 `AudioPlayer`에서 순서대로 재생해야 한다.
- 서버 `response.done`은 응답 생성 완료 신호이고, 단말 재생 완료 신호가 아니다.
- 서버 완료 신호와 단말 재생 완료 시점이 어긋나면 말끝이 잘리거나 마이크 버튼 상태가 실제 청취 상태와 어긋날 수 있다.
- 재생 시작/종료 경계가 너무 급하면 응답 초반이나 말끝에서 소리가 부자연스럽게 들릴 수 있다.

## 원인 파악 계획

이번 문제는 한 번에 원인을 단정하지 않는다.
먼저 실제 기기에서 증상이 재현되는지 확인하고, 재현된다면 오디오 수신, 큐 처리, 로컬 재생, 재생 종료 경계 중 어디에서 문제가 생기는지 좁혀간다.

### 1. 증상 재현과 체감 분류

먼저 사용자가 듣는 문제가 어떤 형태인지 나눈다.

- 단어 일부가 빠진 것처럼 들리는지
- 응답 초반에 소리가 튀는지
- 응답 중간에 말이 빨리 지나가거나 점프하는지
- 응답 마지막 말끝이 잘리는지
- 작은 pop/click 소리만 들리고 문장은 유지되는지

이 분류가 먼저 되어야 한다. 같은 "끊김"처럼 들려도 원인은 큐 누락, 재생 버퍼 부족, 종료 경계 처리처럼 서로 다를 수 있다.

### 2. 오디오 조각이 누락되는지 확인

OpenAI Realtime의 AI 음성은 하나의 완성된 파일이 아니라 여러 개의 짧은 오디오 조각으로 도착한다.
따라서 앱이 이 조각들을 순서대로 받고, 순서대로 재생하려고 하는지 먼저 확인한다.

확인 방향:

- 오디오 조각이 들어올 때마다 큐에 쌓이는지 본다.
- 큐에 쌓인 조각이 재생 경로로 빠져나가는지 본다.
- 오디오 조각의 수신 순서와 재생 순서가 어긋나지 않는지 확인한다.

적용 후보:

- 오디오 조각의 수신/재생 흐름을 비교할 수 있는 최소 로그를 추가한다.
- 큐가 비정상적으로 밀리는 경우만 warning으로 확인한다.

### 3. 재생 시작 경계를 확인

첫 오디오 조각이 오자마자 바로 재생을 시작하면, 스피커가 소비할 버퍼가 충분하지 않을 수 있다.
이 경우 응답 초반에 튐, 짧은 끊김, 첫 단어 부자연스러움이 생길 수 있다.

확인 방향:

- 재생 시작 시점에 오디오 조각이 충분히 준비되어 있는지 본다.
- 재생 시작 직후 사용자 체감상 튐이나 끊김이 있는지 확인한다.
- 시작 안정성을 높이기 위해 짧은 대기가 필요한지 확인한다.

적용 후보:

- 재생 시작 전에 아주 짧게 오디오 조각이 쌓이기를 기다리는 prebuffer를 검토한다.
- 응답 시작이 과하게 늦어지지 않도록 최대 대기 시간을 둔다.
- 실제 기기 청감 결과에 따라 대기 시간과 조각 수를 조정한다.

### 4. 재생 완료 경계를 확인

서버의 `response.done`은 AI가 응답 생성을 끝냈다는 뜻이지, 단말 스피커에서 마지막 소리가 끝났다는 뜻은 아니다.
따라서 서버 완료 신호만 보고 재생을 끝내면 말끝이 잘리거나 마이크 상태가 실제 소리와 어긋날 수 있다.

확인 방향:

- 서버 응답 완료 이후에도 로컬에서 재생할 오디오가 남는지 확인한다.
- 마지막 오디오 조각이 실제로 충분히 재생된 뒤 상태가 종료되는지 확인한다.
- 말끝이 잘리는 체감이 있으면 종료 판단이 너무 빠른지 본다.

적용 후보:

- 서버 완료 신호가 아니라 로컬 재생 상태를 기준으로 재생 완료를 판단한다.
- 단순 시간 계산으로 부족하면 실제 재생 위치를 참고하는 방식을 검토한다.
- 재생이 끝나기 전까지는 AI speaking 상태와 마이크 비활성 상태를 유지한다.

### 5. 종료 시 pop/click 경계를 확인

말끝을 보호하려고 단순히 오래 기다리거나, 반대로 너무 급하게 `pause()` / `flush()`를 호출하면 작은 튐 소리가 날 수 있다.
이 문제는 문장이 잘리는 것과는 다르게, 말은 유지되지만 짧은 pop/click처럼 들릴 수 있다.

확인 방향:

- 응답 종료 직후 작은 튐 소리가 있는지 확인한다.
- 종료 경계에서 `pause()` 또는 `flush()`가 너무 급하게 호출되는지 본다.
- 단순 대기만으로 해결되는지, 오히려 빈 버퍼 상태가 생기는지 확인한다.

적용 후보:

- 응답 종료마다 `flush()`를 바로 호출하지 않는 방향을 검토한다.
- `flush()`는 화면 이탈, stop, release 같은 명시적 정리 경계에만 두는 방향을 검토한다.
- 필요하면 마지막 음성 뒤에 아주 짧은 무음 PCM을 넣어 종료 경계를 부드럽게 만드는 방식을 검토한다.

## 적용 우선순위

수정은 한 번에 크게 바꾸지 않고, 원인 후보를 좁히면서 작은 단위로 적용한다.

1. 먼저 로그를 보강해 오디오 수신, 큐, 재생, 종료 경계를 구분한다.
2. 오디오 조각 순서나 큐 처리 문제가 보이면 재생 큐 정책을 먼저 조정한다.
3. 응답 초반 문제가 보이면 prebuffer를 적용한다.
4. 말끝 잘림이 보이면 로컬 재생 완료 기준을 더 보수적으로 잡는다.
5. pop/click만 남으면 종료 경계의 pause/flush/padding 정책을 조정한다.

## 책임 경계

- `ChatRepositoryImpl`: OpenAI audio delta를 decoding하고 `AIEvent.AudioResponse`로 전달한다.
- `ChatViewModel`: audio response 도착 시 AI speaking 상태와 마이크 입력 방어 상태를 갱신한다.
- `AudioPlayer`: audio chunk를 순서대로 큐잉하고 단말에서 끝까지 재생한다.
- `ChatScreen`: `ChatUiState`에 따라 마이크 버튼과 출력 상태를 표시한다.

이번 작업의 핵심 수정 지점은 `AudioPlayer`다. transport 수신, prompt, SessionMemory 저장 정책은 변경하지 않는다.

---

## 작업 방향

1. AI audio chunk 수신부터 로컬 재생 완료까지 로그를 추가한다.
2. chunk enqueue, playback 시작, playback 완료 시점이 자연스럽게 이어지는지 확인한다.
3. 확인된 원인에 맞춰 queue 정책, 재생 시작 시점, 재생 완료 판단 중 필요한 부분만 수정한다.
4. 마지막 chunk 재생 시간이 지나기 전에는 `isPlaying`을 false로 내리지 않는다.
5. 필요하면 마지막 chunk 뒤에 짧은 무음 padding을 넣어 말끝과 종료 경계를 부드럽게 닫는다.
6. 재생 중 `stopPlaying()`이나 화면 이탈이 발생하면 큐와 상태를 명확히 정리한다.
7. 수정 후 짧은 답변과 긴 답변을 각각 테스트해 끊김 체감이 사라졌는지 확인한다.

## 검증 기준

- 짧은 AI 응답을 여러 번 재생해도 음성이 잘려 들리지 않는다.
- 긴 AI 응답을 재생해도 중간 단어가 빠진 것처럼 들리지 않는다.
- Logcat에서 audio 수신, playback 시작, playback 완료 경계를 확인할 수 있다.
- Logcat에서 응답 종료 경계가 확인 가능하고, 종료 직후 pop/click 여부를 함께 확인할 수 있다.
- AI 음성이 실제로 끝나기 전에는 마이크 버튼이 활성화되지 않는다.
- AI 음성이 끝난 뒤 output level이 0으로 돌아가고 마이크 버튼이 다시 활성화된다.
- final 자막 표시와 usage tracking 로그는 기존처럼 남는다.

- AI 음성 재생 중 화면 이탈
- AI 음성 재생 중 화면 회전
