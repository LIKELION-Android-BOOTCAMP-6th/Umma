# Correction 후속 개선 데모 시나리오

이 문서는 Sprint3 Correction 후속 개선 작업의 UX 시나리오 초안이다.

Sprint2 데모 문서는 구현 완료 기능을 QA/Test Sheet 관점으로 확인하는 성격이 강했다. Sprint3에서는 스프린트 초반 기획 기준으로, 사용자가 어떤 흐름에서 어떤 개선을 체감해야 하는지만 정리한다.

따라서 이 문서에는 세부 테스트 절차, Pass/Fail, 기술 검증 항목을 넣지 않는다. 실제 QA 항목은 구현 범위가 확정된 뒤 별도 Test Sheet에서 작성한다.

## 기준 흐름

기존 Correction의 큰 흐름은 유지한다.

```
Dashboard
→ AI Chat 대화 진행
→ Correction 화면 진입
→ 교정 결과 자동 생성
→ 교정 카드 확인
→ 저장할 카드 선택
→ 저장(Flashcard)
→ Dashboard 복귀
```

Sprint3의 목표는 이 흐름을 새로 만드는 것이 아니라, 교정 결과가 **사용자가 이해하는 언어(primaryLang)로 표시되는지**와 **사용자 실력에 맞는 난이도로 생성되는지**를 개선하는 것이다.

## 시나리오 - COR-FIX-07 교정 결과 언어 기준 정합

사용자는 교정 카드를 볼 때, 카드 앞면 문장과 설명이 자신이 이해하는 학습 기준 언어(primaryLang)로 표시되는 것을 본다. 교정된 문장(뒷면)은 자신이 배우고 있는 언어(selectedLang) 그대로 유지된다.

기존에는 카드 앞면과 설명이 항상 한국어로 고정되어 있어, 한국어를 기준 언어로 쓰지 않는 사용자에게는 설명이 맞지 않았다. 이번 개선으로 Chat / LearningState / Statistics와 동일하게 Correction도 primaryLang과 selectedLang의 역할을 분리해 따른다.

### 사용자 동작 순서

1. 학습 기준 언어(primaryLang)가 한국어, 학습 대상 언어(selectedLang)가 영어인 계정으로 진입한다.
2. AI Chat에서 영어로 몇 턴 대화한다.
3. Correction 화면으로 진입해 교정 결과가 생성될 때까지 기다린다.
4. **[개선] 교정 카드 앞면 문장이 한국어로 표시되는지 확인한다.**
5. **[개선] 교정 설명이 한국어로 표시되는지 확인한다.**
6. **[개선] 교정된 문장(뒷면)은 영어 그대로인지 확인한다.**
7. 학습 기준 언어(primaryLang)가 영어, 학습 대상 언어(selectedLang)가 일본어인 다른 계정으로 같은 흐름을 진행한다.
8. **[개선] 교정 카드 앞면과 설명이 한국어가 아니라 영어로 표시되는지 확인한다.**
9. **[개선] 교정된 문장(뒷면)은 일본어로 표시되는지 확인한다.**
10. 교정 카드를 선택해 저장한다.
11. **[개선] 저장된 Flashcard 앞면/뒷면 언어가 카드에서 본 것과 동일하게 유지되는지 확인한다.**

### UX 포인트

- 교정 카드의 앞면 문장과 설명은 사용자의 학습 기준 언어(primaryLang)를 따라야 한다.
- 교정된 문장과 저장되는 카드 데이터는 학습 대상 언어(selectedLang)를 기준으로 유지되어야 한다.
- 학습 기준 언어가 한국어가 아닌 사용자도 자신이 이해하는 언어로 설명을 받을 수 있어야 한다.
- 언어 설정이 없거나 비어 있어도 교정 생성 자체가 막히지 않아야 한다.
- 기존 카드 선택 / 저장 / 완료 흐름은 변하지 않아야 한다.

## 시나리오 - COR-TUNE-001 실력 기반 교정 난이도 조절

사용자는 자신의 현재 언어 실력에 맞는 교정을 받는다.

초급 사용자에게는 의미를 막는 핵심 오류만 최소한으로 고치고, 쉬운 단어를 유지하며, 설명도 기준 언어로 충분히 풀어 준다. 사용자는 한 번에 너무 많은 교정으로 부담을 느끼지 않는다.

조금 더 높은 수준의 사용자에게는 더 자연스러운 표현이나 구어체, 문장 구조 확장까지 제안한다. 사용자는 단순 오류 수정을 넘어 자신의 수준에 맞춰 표현을 넓혀 가는 교정을 경험한다.

실력 데이터가 아직 충분하지 않은 사용자에게는 안전하게 최소 교정으로 시작한다.

### 사용자 동작 순서

1. 초급 수준의 LangState를 가진 계정으로 AI Chat 대화를 마친다.
2. Correction 화면으로 진입해 교정 결과를 확인한다.
3. **[개선] 의미를 막는 핵심 오류 위주로 간단히 교정되고, 설명이 기준 언어로 쉽게 제공되는지 확인한다.**
4. **[개선] 어려운 새 단어나 복잡한 문장 구조를 한 번에 밀어 넣지 않는지 확인한다.**
5. 중급 이상 수준의 LangState를 가진 계정으로 같은 흐름을 진행한다.
6. **[개선] 더 자연스러운 표현이나 구어체, 문장 구조 확장 제안이 포함되는지 확인한다.**
7. 반복 약점(예: 시제, 관사)이 쌓인 사용자로 교정을 진행한다.
8. **[개선] 자연스러운 범위에서 해당 약점을 가볍게 짚어 주는지 확인한다.**
9. 실력 데이터가 거의 없는 신규 사용자로 교정을 진행한다.
10. **[개선] 무리한 교정 대신 안전한 최소 교정으로 시작하는지 확인한다.**

### UX 포인트

- 사용자는 자신의 수준보다 과하게 어려운 교정을 받지 않아야 한다.
- 초급자는 최소 교정과 쉬운 설명, 중급 이상은 자연스러운 표현 확장을 경험해야 한다.
- 반복 약점이 있으면 자연스러운 기회에 한 번만 가볍게 도와야 한다.
- 실력 데이터가 부족해도 교정이 불안정해지지 않고 안전한 최소 교정으로 시작해야 한다.
- 교정 카드 표시 / 선택 / 저장 흐름은 그대로이며, 교정 결과에 함께 만들어지는 내부 학습 신호(learningSignal)는 화면에 노출되지 않는다.

## 시나리오 - COR-TUNE-002 교정 관찰 신호 기반 학습 정렬

사용자는 교정을 받을수록, 다음 교정과 복습이 자신이 실제로 자주 틀리는 지점에 점점 더 잘 맞춰지는 것을 체감한다.

교정 AI는 사용자의 실력 점수나 레벨을 판정하지 않는다. 대신 교정하면서 이미 보고 있는 정보(어떤 종류의 오류였는지, 어떤 식으로 개선했는지, 말투와 심각도 등)를 내부 학습 신호로 정리해 장기 학습 상태에 넘긴다. 이 신호는 화면에 보이지 않지만, 쌓일수록 시스템이 사용자의 약점을 더 정확히 이해하게 한다.

핵심은 사용자가 추가로 무언가를 입력하거나 설정하지 않아도, 평소처럼 교정을 받고 저장하는 것만으로 학습 정렬이 좋아진다는 점이다.

### 사용자 동작 순서

1. AI Chat에서 대화한 뒤 Correction 화면으로 진입해 교정 결과를 확인한다.
2. 교정 카드를 평소처럼 확인하고 일부를 선택해 저장한다.
3. **[개선] 교정 카드 앞면/뒷면/설명 표시는 기존과 동일하며, 신호 수집 때문에 화면에 새로운 항목이 추가되거나 흐름이 달라지지 않는지 확인한다.**
4. 같은 종류의 오류(예: 시제, 관사)를 반복해서 포함한 대화를 여러 번 진행하고 교정을 받는다.
5. **[개선] 교정을 반복할수록 이후 교정·복습이 자신이 자주 틀리는 지점 위주로 정렬되어 가는지 체감한다.**
6. 교정 도중 일부 신호가 불완전하거나 모호한 경우에도 교정 카드 생성·저장이 정상 동작하는지 확인한다.

### UX 포인트

- 사용자는 신호 수집을 위해 추가 입력이나 설정을 하지 않는다. 평소 교정 흐름 그대로다.
- 내부 학습 신호는 화면에 노출되지 않는다. 사용자는 "점점 내 약점에 맞춰지는 교정"이라는 결과만 체감한다.
- 교정 AI는 능력 점수·레벨을 판정하지 않고, 교정 과정에서 관찰한 내용만 신호로 넘긴다.
- 신호가 모호하거나 누락되어도 교정 카드 표시·선택·저장 흐름은 영향받지 않는다.

## 시나리오 - COR-TUNE-002-FIX 불확실한 신호의 안전한 처리

사용자는 내부 학습 신호가 불완전하거나 신뢰하기 어려운 경우에도, 자신이 보는 교정 카드와 저장 결과가 흔들리지 않는 것을 경험한다.

학습 신호는 장기 학습 상태를 계산하는 입력이다. 그래서 신뢰할 수 없는 신호(의미 보존 여부가 확인되지 않았거나, 정의되지 않은 값이 섞인 경우)는 일부만 살려 반영하기보다 그 신호 전체를 안전하게 버린다. 이렇게 해야 검증되지 않은 관찰이 사용자의 장기 실력 추정을 왜곡하지 않는다.

중요한 것은, 신호를 버리는 일이 사용자에게 보이는 교정 결과에는 전혀 영향을 주지 않는다는 점이다. 교정 문장과 저장 카드는 그대로 살아남는다.

### 사용자 동작 순서

1. AI Chat 대화 후 Correction 화면에서 교정 결과를 확인한다.
2. 교정 카드를 선택해 저장한다.
3. **[개선] 내부 신호 중 일부가 불확실해 버려지더라도, 교정 카드와 저장된 Flashcard는 정상적으로 표시·저장되는지 확인한다.**
4. 다양한 대화/교정을 반복하며 교정 흐름이 중간에 끊기거나 빈 카드가 생기지 않는지 확인한다.
5. **[개선] 신뢰할 수 없는 신호가 장기 학습 상태에 반영되지 않아, 시간이 지나도 교정 정렬이 엉뚱한 방향으로 흐르지 않는지 체감한다.**

### UX 포인트

- 신호를 버리는 처리는 사용자에게 보이지 않는다. 교정 카드/Flashcard 저장 흐름은 항상 무손상이다.
- 불확실한 신호는 일부만 반영하지 않고 안전하게 전체를 버려, 장기 실력 추정이 왜곡되지 않는다.
- 의미가 바뀌었을 수 있는 교정은 검증되지 않은 "의미 보존"으로 단정하지 않는다.
- 사용자는 "교정이 갑자기 이상해지지 않고 일관되게 내 약점을 따라온다"는 안정감을 체감한다.

## 시나리오 - COR-TUNE-003 교정 성장 단계(Growth Band) 세분화

사용자는 자신의 현재 언어 실력에 맞는 "다음 단계" 교정을 받는다.

COR-TUNE-001이 교정 난이도를 4단계로 조절했다면, COR-TUNE-003은 이를 의미 전달 → 패턴 → 문장 형태 → 일상 표현 → 연결 표현 → 뉘앙스의 6단계 성장 흐름으로 더 세분화한다. 핵심은 "가장 완벽한 문장"이 아니라 "지금 사용자가 이해하고 다시 말할 수 있는 조금 더 나은 문장"을 만드는 것이다.

아주 낮은 단계의 사용자에게는 의미가 통하도록 매우 짧은 문장으로 정리하고 새 표현을 거의 넣지 않는다. 중간 단계 사용자에게는 한 번에 하나의 핵심 패턴을 고치거나 짧은 일상 표현 하나를 더한다. 높은 단계 사용자에게는 collocation, register, 뉘앙스 같은 자연스러움을 다듬는다. 모든 단계에서 사용자의 원래 의도와 문장 길이는 과하게 바뀌지 않는다.

### 사용자 동작 순서

1. 실력 데이터가 거의 없는 신규 사용자로 교정을 진행한다.
2. **[개선] 의미가 통하는 매우 짧은 문장으로 정리되고, 새 표현이 거의 추가되지 않는지 확인한다.**
3. 단어·짧은 구는 가능하지만 문장 뼈대가 약한 사용자로 교정을 진행한다.
4. **[개선] 여러 오류를 한꺼번에 고치지 않고, 핵심 패턴 하나 위주로 교정되는지 확인한다.**
5. 짧은 문장은 가능하지만 어순·시제가 흔들리는 사용자로 교정을 진행한다.
6. **[개선] 문장이 완성된 형태로 다듬어지고, 아주 작은 구조 확장 하나만 허용되는지 확인한다.**
7. 일상 대화가 가능한 사용자로 교정을 진행한다.
8. **[개선] 더 자연스러운 일상 표현 하나가 추가되되, 길고 어려운 고급 문장으로 바뀌지는 않는지 확인한다.**
9. 의미 전달이 안정적인 고급 사용자로 교정을 진행한다.
10. **[개선] register, 뉘앙스, 원어민식 선택을 세밀하게 다듬어 주는지 확인한다.**
11. 실력 데이터가 충분하지 않거나 지표가 서로 충돌하는 사용자로 교정을 진행한다.
12. **[개선] 하나의 높은 지표만으로 무리하게 높은 단계로 올라가지 않고, 한 단계 보수적으로 교정되는지 확인한다.**

### UX 포인트

- 교정 강도는 "더 완벽한 문장"이 아니라 "지금 따라갈 수 있는 다음 단계 문장"을 기준으로 한다.
- 낮은 단계일수록 의미 보존과 짧은 문장이 우선이고, 새 표현·문장 확장은 제한된다.
- 높은 단계일수록 자연스러움·뉘앙스·register를 다룰 수 있다.
- 반복 약점이 의미 전달 오류나 핵심 문법에 쏠리면 자연스러움 개선보다 패턴 안정화를 먼저 한다.
- 실력 근거가 부족하거나 지표가 충돌하면 안전하게 한 단계 낮은 교정으로 시작한다.
- 성장 단계 이름이나 능력 점수·레벨은 사용자 화면이나 교정 문구에 노출되지 않는다. 사용자는 결과(쉬운/자연스러운 교정)만 체감한다.
- 고급 단계(ConnectedExpression/NuanceRefine)에서는 교정 설명이 primaryLang이 아닌 학습 대상 언어(target language) 중심으로 제공될 수 있다. 이는 의도된 동작이며 오류가 아니다(COR-FIX-07의 "설명=항상 primaryLang" 전제는 낮은 단계 기준이다).

## 시나리오 - COR-TUNE-003-FIX 고급 단계 설명 언어 일관성 + 신호 누락 방지

사용자는 고급 단계에서 받는 교정 설명의 언어가 일관되게 적용되는 것을 경험하고, 그 뒤에서는 교정 분석 데이터가 누락 없이 학습 상태에 반영된다.

COR-TUNE-003이 6단계 성장 정책을 도입하면서, 고급 단계에서는 설명을 학습 대상 언어(target language) 중심으로 제공하도록 바뀌었다. 그런데 기존 응답 규칙은 설명을 항상 기준 언어(primaryLang)로 쓰라고 고정하고 있어 두 지시가 충돌했다. 이 충돌을 정리해, 고급 사용자가 받는 설명 언어가 단계 정책에 맞춰 안정적으로 적용되게 한다.

또한 교정 변경 지점(edit) 단위의 내부 분석 값이 정의된 목록 밖으로 들어오면 해당 교정의 학습 신호가 통째로 누락되던 문제를 막기 위해, 허용된 값만 쓰도록 안내를 강화한다. 사용자에게 보이는 교정 카드는 이전과 동일하며, 달라지는 것은 "뒤에서 학습에 반영되는 데이터가 새지 않는다"는 점이다.

### 사용자 동작 순서

1. 의미 전달이 안정적인 고급 단계 사용자로 교정을 진행한다.
2. **[개선] 교정 설명 언어가 단계 정책(고급 단계는 학습 대상 언어 중심)에 맞춰 일관되게 제공되고, 초급 단계의 기준 언어 설명 규칙과 충돌하지 않는지 확인한다.**
3. 낮은 단계 사용자로 같은 흐름을 진행한다.
4. **[개선] 낮은 단계에서는 설명이 기존과 동일하게 기준 언어(primaryLang)로 제공되어 변화가 없는지 확인한다.**
5. 다양한 교정을 반복하며 교정 카드 표시·선택·저장 흐름이 그대로 유지되는지 확인한다.
6. **[개선] 교정 변경 지점 분석 값이 정의된 목록 밖으로 들어오는 경우에도, 학습에 반영되는 신호가 통째로 누락되지 않도록 처리되는지(내부 동작) 확인한다.**

### UX 포인트

- 고급 단계 설명 언어는 성장 정책 하나로 결정되어, 단계가 올라가도 설명 언어 지시가 충돌하거나 흔들리지 않는다.
- 낮은 단계의 설명 언어 경험은 기존과 동일하다(동작 변화 없음).
- 교정 변경 지점의 내부 분석 값은 허용된 목록만 사용하도록 안내되어, 학습 신호가 조용히 누락되지 않는다.
- 사용자에게 보이는 교정 카드·설명·저장 흐름은 그대로이며, 이 작업은 뒤에서 일관성과 데이터 정합성을 높이는 정리다.
