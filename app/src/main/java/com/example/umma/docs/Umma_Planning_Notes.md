# Umma – 대화 학습 기획 및 설계 노트1

## 0. 개요

Umma는 ‘공부를 시작하는 앱’이 아니라

**말하고 싶어지는 순간을 만드는 음성 중심 언어 학습 앱**이다.

대화 학습은 Umma의 핵심 기능이며,

텍스트 입력이나 문제 풀이가 아닌 **실제 말하기 경험**을 중심으로 설계된다.

구현에서 참조하는 상태 모델 이름은 `LangState`, `DashSummary`, `UserLangPref`, `GlobalLangState`다.

---

## 1. 대화 학습의 기본 원칙

### 1.1 음성 대화 ONLY

- 텍스트 입력은 지원하지 않는다
- 키보드 UI는 존재하지 않는다
- 사용자는 반드시 **말해야만** 앱과 상호작용할 수 있다

**의도**

- 채팅 앱과의 명확한 분리
- “생각 → 말하기” 흐름을 끊지 않기 위함

---

### 1.2 언어 레벨은 선택하지 않는다

- 레벨 선택 화면 없음
- 테스트 없음
- 튜토리얼에서조차 레벨을 묻지 않는다

AI는 다음 요소를 기반으로 사용자의 언어 능력을 **대화 중 추론**한다.

- 발화 길이
- 침묵 시간
- 문장 구조의 복잡도
- 반복되는 단어와 표현
- 문법 오류 패턴

이 추론 결과에 따라:

- 말하는 속도
- 문장 길이
- 단어 난이도
가 **자동으로 조절된다**

---

## 2. AI의 대화 방식

### 2.1 AI는 ‘응답자’가 아니라 ‘리더’다

AI는 사용자의 말에 단순히 답변만 하지 않는다.

- 사용자의 발화 이후 자연스럽게 질문을 이어간다
- 침묵이 길어질 경우 대화를 다시 열어준다
- 사용자의 반응에 따라 주제를 확장하거나 전환한다

**중요한 점**

- ‘다음 질문’ 버튼 없음
- ‘주제 선택’ UI 없음
- 대화의 흐름은 AI가 책임진다

---

### 2.2 모국어는 보조 수단으로만 사용된다

- 기본 대화 언어는 학습 언어
- 필요할 경우 **모국어를 아주 제한적으로 섞는다**

사용 기준:

- 의미 오해가 발생했을 때
- 핵심 단어 하나만 짚어줘야 할 때
- 대화 흐름이 끊길 위험이 있을 때

**금지**

- 장문 설명
- 번역 모드
- 문장 전체 번역

모국어는 “이해를 돕기 위한 힌트”로만 사용된다.

---

## 3. 대화 화면 UI 구성

### 3.1 기본 화면 요소

- 중앙 또는 하단에 마이크 버튼
- 중앙 이미지를 중심으로 현재 입력/출력 상태를 보여주는 비주얼 피드백
- AI 음성 출력
- 최소한의 시각 요소

의도적으로 다음 요소들은 배제한다.

- 텍스트 입력창
- 문장 목록
- 학습 지표
- 점수 / 레벨 표시

---

### 3.2 AI 음성 자막 기능

- AI 음성을 텍스트로 볼 수 있는 옵션 제공
- 기본 설정은 OFF
- 자막 토글을 On으로 켰을 때만 마지막 턴 자막 표시
- 자막은 AI 응답용이며, 입력 강도나 재생 상태는 중앙 비주얼이 맡는다

**설계 의도**

- 듣기에 집중하도록 유도
- 읽기 의존 방지
- 필요할 때만 사용하는 안전장치

---

## 4. 대화 데이터와 기억

Umma의 모든 대화는 **데이터베이스를 기반으로 이어진다.**

AI는 다음 정보를 참고한다.

- 사용자의 평균 발화 길이
- 자주 사용하는 표현
- 자주 막히는 지점
- 이전에 다뤘던 대화 주제 요약
- 마지막 대화 이후 경과 시간

이를 통해:

- 대화 난이도가 갑자기 리셋되지 않으며
- 같은 질문이 반복되지 않고
- 이전 대화의 연속성이 유지된다

사용자는 명시적으로 ‘기억’을 관리하지 않는다.

기억은 **AI의 태도와 대화 방식**으로만 드러난다.

---

## 5. 대화 학습의 한 줄 정의

> 말하면 시작되고,
> 
> 
> AI가 맞춰주고,
> 
> 막히면 도와주고,
> 
> 침묵하면 이끌고,
> 
> 모든 대화는 기억된다.
> 

# Umma – 문장 교정 설계 노트

## 0. 교정 기능의 위치

문장 교정은 **대화가 끝난 이후**에만 실행된다.

- 대화 도중 자동 교정 ❌
- 사용자의 발화 흐름을 끊지 않는다
- 교정은 “학습 단계”에서만 등장한다

교정의 목적은 틀린 문장을 지적하는 것이 아니라,

**사용자가 정말 말하고 싶었던 문장을 가장 자연스럽게 다시 만들어주는 것**이다.

---

## 1. 교정 대상 데이터

교정은 다음 데이터를 기반으로 한다.

- 사용자가 실제로 말한 음성 발화 turn
- 발화의 문맥 (앞뒤 대화 흐름)
- 현재 선택 언어의 Session Memory `recentFullContext`
- 현재 추정된 언어 능력(LangState Snapshot)

단일 문장이 아니라 **의미 단위의 발화 묶음**을 기준으로 분석한다.

MVP에서는 자주 하는 실수나 과거 오류 패턴을 별도 참조 데이터로 저장하지 않는다.
해당 기능은 추후 교정 성능 고도화 단계에서 별도 데이터 구조를 추가해 구현한다.

---

## 1.1 추후 고도화: 자주 하는 실수 반영

MVP 이후에는 사용자의 자주 하는 실수와 반복되는 오류 패턴을 별도 참조 데이터로 축적하여,
교정 문장 선정과 설명 방식에 반영한다.

추후 확장 예시:

- 자주 틀리는 문장 구조
- 반복되는 어휘 선택 실수
- 자주 막히는 표현 패턴
- 교정받은 표현의 재등장 여부
- Flashcard 저장 후 실제 대화에서 다시 사용되는지 여부

이 데이터는 MVP의 `recentFullContext`나 `LangState` 필드에 미리 넣지 않는다.
교정 성능 고도화가 필요한 시점에 별도 데이터 구조로 추가한다.

---

## 2. 교정의 핵심 원칙

### 2.1 “정말 표현하고 싶었던 문장”을 먼저 파악한다

교정은 문법을 먼저 보지 않는다.

1. 사용자의 의도 추론
2. 말하려던 핵심 의미 복원
3. 그 의미를 가장 자연스럽게 표현할 수 있는 문장 생성

**중요**

- 단어 하나만 고치는 방식 ❌
- 직역 기반 교정 ❌

---

### 2.2 이번 대화에서 학습 가치가 높은 문장을 우선한다

다음 유형의 문장을 우선적으로 교정 후보로 선정한다.

- 이번 `recentFullContext` 안에서 의미가 분명한 사용자 발화
- 사용자의 현재 LangState 대비 교정 가치가 높은 문장
- 사용자가 말할 때 막히거나 어색하게 표현한 지점

MVP 교정은 누적 오류 패턴이 아니라 이번 대화의 user turn과 현재 LangState를 중심으로 수행한다.

---

### 2.3 올바르지 않은 어휘 선택을 교정한다

문법적으로 틀리지 않았더라도 교정 대상이 된다.

- 의미는 맞지만 어색한 단어
- 구어체에서 잘 쓰지 않는 표현
- 문맥에 비해 과도하게 딱딱한 단어

목표는:

> 원어민이 실제 대화에서 선택할 단어
> 

---

### 2.4 결과 문장은 반드시 구어체여야 한다

교정 결과는 다음 기준을 따른다.

- 실제 대화에서 쓰이는 말투
- 교과서적 문장 ❌
- 설명용 문장 ❌

“맞는 문장”이 아니라

**“이 상황에서 진짜 이렇게 말한다”**가 기준이다.

---

## 3. 난이도 조절 원칙 (10% 성장)

교정 문장은 사용자의 현재 언어 능력을 기준으로

**약 10% 정도 어려운 수준**을 목표로 한다.

조절 요소:

- 문장 구조의 확장
- 더 자연스러운 동사 선택
- 자주 쓰이지만 아직 익숙하지 않은 표현

금지:

- 사용자의 수준을 크게 벗어나는 고급 표현
- 이해 없이 외워야 하는 문장

---

## 4. 교정 문장 선정 규칙

### 4.1 기본 교정 문장 수

- 기본적으로 **10개의 문장**을 교정 결과로 제공한다
- 모든 문장은 실제 사용자의 발화에서 파생된다

### 4.2 교정 문장 유형

10개 문장은 다음 기준을 복합적으로 반영한다.

- 핵심 의미 문장
- 자주 틀리는 문장
- 어휘 선택이 부자연스러웠던 문장
- 앞으로 재사용 가능성이 높은 문장

---

## 5. 교정 결과 UI 흐름

### 5.1 교정 결과 확인

- 교정된 문장 리스트 제공
- 사용자는 **읽기만** 할 수도 있고
- 마음에 드는 문장을 **선택**할 수도 있다

자동 저장 ❌

자동 학습 연결 ❌

---

### 5.2 사용자 선택 기반 저장

- 사용자가 선택한 문장만 다음 단계로 넘어간다
- 선택하지 않은 문장은 저장되지 않는다

선택 = “이 문장은 내 것으로 만들고 싶다”는 의미

---

## 6. 플래시카드 생성 규칙

선택된 문장은 플래시카드로 변환된다.

### 6.1 카드 구조

- 앞면: 모국어 의미
- 뒷면: 교정된 문장
- 작은 버튼 형태의 발음 듣기 기능 포함

### 6.2 카드의 역할

- 문법 설명 ❌
- 장문 해설 ❌

카드는 **다시 말해보기 위한 재료**다.

---

## 7. 교정 기능의 한 줄 정의

> 교정은 틀린 문장을 고치는 일이 아니라,
> 
> 
> 말하고 싶었던 문장을
> 
> 다시 말할 수 있게 만드는 과정이다.
> 

# Umma – 플래시카드 학습 설계 노트

## 0. 플래시카드 학습의 역할

플래시카드 학습은

대화와 교정에서 만들어진 문장을 **내 것으로 굳히는 단계**다.

Umma의 플래시카드는:

- 단어 암기용이 아니라
- 문법 설명용이 아니라
- **다시 말해보기 위한 말의 재료**다.

---

## 1. 언어별 플래시카드 저장

플래시카드는 **학습 언어별로 분리 저장**된다.

- 사용자가 어떤 언어로 대화했는지에 따라
- 교정 결과 문장은 해당 언어의 카드 덱에 저장된다

예:

- 영어로 대화 → 영어 학습 카드
- 일본어로 대화 → 일본어 학습 카드

사용자는 별도의 저장 언어를 선택하지 않는다.

언어는 **대화 자체가 결정한다.**

---

## 2. 학습 언어 선택

플래시카드 학습을 시작할 때,

사용자는 **학습하고자 하는 언어를 선택**한다.

- 현재 저장된 카드가 있는 언어만 표시
- 언어 선택은 학습 맥락 전환을 위한 최소한의 조작

선택 이후:

- 해당 언어의 카드만 학습 대상으로 노출된다

---

## 3. 반복 학습 구조 (망각곡선 기반)

플래시카드는 Anki와 유사하게

**망각곡선에 기반한 반복 학습 구조**를 따른다.

- 모든 카드는 노출 시점을 가진다
- 시간이 지나면 다시 학습 대상으로 등장한다
- 무작위 노출 ❌
- 사용 빈도 기반 노출 ❌

목표는:

> “잊어버릴 즈음 다시 만나는 것”
> 

---

## 4. MVP 평가 시스템

### 4.1 학습 방식

- 카드가 노출되면 문장을 **눈으로만 보는 것이 아니라**
- 사용자가 머릿속으로 떠올리거나 **직접 말해본다**
- 이후 사용자가 5단계 버튼으로 자신의 기억 정도를 평가한다

### 4.2 MVP 5단계 평가 버튼

MVP에서는 AI가 발화를 자동 평가하지 않는다.

사용자는 Anki와 유사하게 아래 5단계 중 하나를 선택한다.

| 버튼 | 의미 | 다음 노출 |
| --- | --- | --- |
| 완전히 몰랐음 | Blackout | 당일 재노출 |
| 생각났지만 틀림 | Wrong | 1일 후 |
| 힘겹게 맞음 | Hard | 3일 후 |
| 맞음 | Good | 현재 interval x 2.5 |
| 완벽하게 맞음 | Easy | 현재 interval x 3.5 |

### 4.3 다음 노출 시점 결정

시스템은 사용자가 선택한 버튼을 기준으로:

- interval
- ease_factor
- next_review_at

을 업데이트한다.

### 4.4 향후 확장: AI 발화 평가

MVP 이후에는 사용자의 발화를 기준으로 AI가 다음 요소를 분석할 수 있다.

- 문장의 완성도
- 의미 전달 여부
- 실수의 종류 (어휘 / 구조 / 조사 등)
- 발화 속도
- 망설임과 침묵

이 확장 단계에서는 AI 분석 결과를 기반으로 다음 노출 시점을 자동 결정할 수 있다.

# Umma – 학습 진척도 설계 노트

## 0. 학습 진척도의 역할

학습 진척도는 사용자를 자극하거나 경쟁시키기 위한 기능이 아니다.

- 연속 학습 일수 ❌
- 랭킹 ❌
- 점수 중심 평가 ❌

학습 진척도의 목적은 단 하나다.

> “나는 지금,
> 
> 
> 예전보다 어떻게 달라졌는가?”
> 

---

## 1. 진척도 확인 방식

사용자는 자신의 언어 학습 진척도를

**차트와 수치**를 통해 확인할 수 있다.

단일 점수로 요약하지 않고,

여러 요소를 분리하여 보여준다.

---

## 2. 진척도 측정 기준

학습 진척도는 시간의 흐름에 따라 다음 요소들을 기반으로 분석된다.

### 2.1 어휘 난이도의 변화

- 사용자가 사용하는 단어들의 평균 난이도
- 초급 단어 → 중급 / 구어체 표현으로의 이동
- 반복 사용되는 핵심 어휘의 안정화 여부

---

### 2.2 구사 어휘의 개수

- 실제 대화와 발화에서 사용된 고유 어휘 수
- 단순 노출이 아닌 **직접 말한 단어만** 포함
- 시간이 지남에 따라 어휘 풀이 확장되는지 확인

---

### 2.3 문장 구조의 변화

- 단문 위주의 발화에서
- 연결된 문장, 확장된 구조로의 변화

예:

- 단일 문장
- 접속사 사용
- 이유, 감정, 조건을 포함한 구조

문장의 “길이”가 아니라

**구조적 다양성**을 기준으로 평가한다.

---

### 2.4 문어체 → 구어체로의 변화

- 교과서적인 표현 비중
- 실제 대화에서 쓰이는 구어체 표현 비중
- 자연스러운 축약, 관용 표현 사용 여부

목표는:

> 맞지만 어색한 문장 →
> 
> 
> 자연스럽게 쓰이는 말
> 

---

## 3. 차트 구성 방식

### 3.1 시간 기반 시각화

- 모든 지표는 시간의 흐름에 따라 표시된다
- 하루 단위가 아닌 **누적 변화 추세**를 중심으로 한다

급격한 상승이나 하락보다는

“완만한 변화”를 보여주는 데 집중한다.

---

### 3.2 수치 + 시각 자료 병행

- 각 항목은 수치로도 확인 가능
- 동시에 그래프 형태로 시각화

수치는 비교를 위한 것이 아니라

**변화를 인지하기 위한 보조 수단**이다.

---

## 4. 기본 표시 언어 규칙

학습 진척도 화면에 처음 진입했을 때:

- 사용자가 선택한 **주 학습 언어**, 또는
- 가장 많이 학습한 언어를

기본 언어로 자동 표시한다.

사용자는:

- 다른 언어를 선택하여
- 언어별 진척도를 개별적으로 확인할 수 있다

---

## 5. 언어 간 진척도 분리 원칙

- 언어별 진척도는 서로 합산되지 않는다
- 비교 랭킹을 제공하지 않는다
- 각 언어는 독립적인 학습 흐름을 가진다

목표는:

> “이 언어에서 나는 어디쯤 왔는가”
> 

---

## 6. 학습 진척도의 한 줄 정의

> 학습 진척도는
> 
> 
> 얼마나 많이 했는지를 보여주는 것이 아니라,
> 
> 어떻게 달라졌는지를 보여준다.
>
